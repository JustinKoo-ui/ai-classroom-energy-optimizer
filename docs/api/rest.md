# REST API v1

Base path: `/api/v1`. JSON fields use `snake_case`; timestamps are UTC ISO 8601;
identifiers are UUID strings. OpenAPI generated by FastAPI is the executable
contract once routes are implemented.

## Cross-cutting behavior

- Authenticate with `Authorization: Bearer <JWT>`.
- Roles: `viewer` (read), `operator` (manual control and schedules), `admin`
  (configuration and policy administration).
- Mutating request bodies include no server-owned IDs or timestamps unless
  shown. Unknown fields are rejected.
- Manual commands require `Idempotency-Key: <unique string>`. Retrying with the
  same key and identical body returns the original result; a different body is
  `409 Conflict`.
- List endpoints accept `limit` (default 50, maximum 200) and opaque `cursor`.
- Historical endpoints accept `from`, `to` and optional `bucket` where relevant.
- `202 Accepted` means a request entered the policy/command workflow. It never
  means the physical device has changed.

Successful collection responses:

```json
{
  "items": [],
  "next_cursor": null
}
```

Error response:

```json
{
  "error": {
    "code": "device_offline",
    "message": "The device is not available for control.",
    "details": {"device_id": "uuid"},
    "trace_id": "uuid"
  }
}
```

## Sites and classrooms

|---|---|---:|---|
| GET | `/sites` | viewer | List authorized sites |

| POST | `/sites` | admin | Create site |

## Devices and control

| Method | Path | Role | Result |
|---|---|---:|---|
| GET | `/classrooms/{classroom_id}/devices` | viewer | Devices, capabilities and latest state |
| POST | `/classrooms/{classroom_id}/devices` | admin | Register device |
| GET | `/devices/{device_id}` | viewer | Device configuration and state |
| PATCH | `/devices/{device_id}` | admin | Change metadata/capabilities/enabled flag |
| POST | `/devices/{device_id}/commands` | operator | Submit one-time manual control request |
| GET | `/devices/{device_id}/commands` | viewer | Command history |
| GET | `/commands/{command_id}` | viewer | Decision, delivery and acknowledgement status |
| POST | `/commands/{command_id}/cancel` | operator | Cancel only if not already applied |

Manual command request:

```json
{
  "action": "set_power",
  "value": {"on": true},
  "reason": "Lecturer requested cooling during an occupied class",
  "expires_in_seconds": 30
}
```

Response (`202` when policy evaluation has been accepted for processing, or
`200` when evaluated synchronously):

```json
{
  "request_id": "uuid",
  "decision_id": "uuid",
  "decision": "allowed",
  "reason_codes": ["authorized_manual_request", "device_available"],
  "command_id": "uuid",
  "command_status": "queued"
}
```

An allowed decision is not an applied command. Clients follow the command using
`GET /commands/{id}` or WebSocket `command.status` events.

## Manual overrides

| Method | Path | Role | Result |
|---|---|---:|---|
| GET | `/classrooms/{classroom_id}/overrides` | viewer | Active/future overrides |
| POST | `/devices/{device_id}/overrides` | operator | Create time-bounded override |
| GET | `/overrides/{override_id}` | viewer | Override details |
| POST | `/overrides/{override_id}/cancel` | operator/owner | End override early |

Create override request:

```json
{
  "mode": "force_state",
  "value": {"on": true, "setpoint_c": 26.0},
  "starts_at": "2026-08-14T03:30:00Z",
  "ends_at": "2026-08-14T05:30:00Z",
  "reason": "Scheduled examination"
}
```

Overrides do not bypass hardware limits, offline/fault checks or authorization.

## Schedules

| Method | Path | Role | Result |
|---|---|---:|---|
| GET | `/classrooms/{classroom_id}/schedules` | viewer | List schedules |
| POST | `/classrooms/{classroom_id}/schedules` | operator | Create schedule |
| GET | `/schedules/{schedule_id}` | viewer | Schedule details |
| PATCH | `/schedules/{schedule_id}` | operator | Update and increment version |
| DELETE | `/schedules/{schedule_id}` | operator | Disable (soft delete) schedule |
| POST | `/schedules/{schedule_id}/enable` | operator | Enable schedule |
| POST | `/schedules/{schedule_id}/disable` | operator | Disable schedule |
| GET | `/schedules/{schedule_id}/runs` | viewer | Execution/skip/denial history |

Schedules use an RFC 5545 `rrule`, an IANA `timezone`, a target device and a
requested action/value. Each run enters the same deterministic policy as a
manual or automatic request.

## Common status codes

- `200` read/update or synchronous known result.
- `201` resource created.
- `202` workflow accepted; observe later status.
- `400` invalid semantics; `401` unauthenticated; `403` unauthorized.
- `404` resource absent or outside caller scope.
- `409` idempotency/version/state conflict.
- `422` invalid fields; `429` command rate limit.
- `503` required dependency unavailable; no command is assumed applied.
